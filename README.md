# quiet-lantern

Small Russian mobile helper published at https://petkuz.github.io/quiet-lantern/index.html?v=5 using free GitHub Pages. No external browser dependencies, analytics, or router password collection. HTML, scripts, styles, and payload requests use release version 5 to avoid mixing previously cached files; increment the version together for future releases. The previous release-4 URL continues to support both father profiles.

Locations: Город and Дача use LuCI at `192.168.80.1`; Домашний роутер uses `192.168.1.1`. Each has its own encrypted installer and dedicated relay identity. Home uses `ql-home`, loopback port 18584, and server-side ClientAliveInterval 30 / ClientAliveCountMax 3. Home provisioning changes neither father identity nor its settings. The existing home-router-remote management path is separate and remains unchanged. Adding a page choice never installs anything on a router.

Release 5 preserves the city/dacha installer bytes and key identities against an outside-Git release-4 baseline; the installer version stays 4. The expected LAN is substituted per profile. A build/audit fails if the protected father installer bytes differ. `scripts/provision-home.sh` provisions only the new public home identity, with SSH configuration backups and protected-file hash checks. Private home key material is generated and retained locally; only its public key goes to the VPS.

`docs/` is the complete deployable artifact. `payload.json` contains authenticated ciphertext, never plaintext bootstrap credentials. The QR contains only the canonical HTTPS URL. Visiting or unlocking does not register a device or install anything.

Encryption: WebCrypto PBKDF2-HMAC-SHA256, 900,000 iterations, random 16-byte salt, AES-256-GCM with random 12-byte IV. A predictable numeric password remains vulnerable to offline guessing. This is not strong authentication; a discreet name and noindex are not security controls. Anyone holding the password can extract the dedicated tunnel identities. Those identities permit only their assigned VPS loopback listener, never a shell, local forwarding, public listener, agent, or PTY. They are reusable, not one-time enrollment. Revoke/rotate after suspected disclosure; old Git history retains old ciphertext.

Build locally on Windows: `node scripts/build.mjs`. `relay.json` defines the current SSH relay and per-profile ports. Required private inputs live outside Git under `%LOCALAPPDATA%/quiet-lantern/` and the administrator public key stays under the local SSH directory. Never copy private inputs into the repository or Actions. `npm test` tests authenticated encryption, binary octal encoding, and clipboard/new-tab sequencing, including blocked popups. Set `QL_TEST_SSH` to a trusted SSH alias to additionally verify byte reconstruction with actual BusyBox ash. `scripts/test-installer.py` runs unprivileged beside a copy of `installer.sh` on a POSIX system with BusyBox, using isolated temporary paths and explicit command mocks. It checks installation, binary reconstruction, safe upgrade, preserved configuration, repeat no-op, disabled state, profile mismatch, missing SSH listener, and unknown-VPN fallback. The VPS test is an explicit administrative operation, not a CI job.

Installer requires compatible OpenWrt/procd, Dropbear client with BatchMode/StrictHostKeyChecking/ExitOnForwardFailure, IPv4 LAN 192.168.80.1 and an existing IPv4 SSH listener accepting loopback on port 22. Binary key material is reconstructed with shell-builtin `printf '%b'` and octal escapes; no `base64` executable is required. It does not install packages, change interfaces or VPN server configuration, or enable router password authentication. Unsupported firmware stops and logs to `quiet-lantern`. Existing rc.local text must be preserved, with the block inserted before its final `exit 0`. It adds a persistent procd service and preserves existing authorized keys. Initial setup backs up affected files under `/etc/quiet-lantern/`; subsequent rc.local executions are no-ops. An incomplete installation stops for manual inspection.

When a recognised `inet v2raya` table exists, the relay worker inserts only destination relay IPv4 / TCP port 22 exceptions at the beginning of `tp_out` and `tp_rule`, clearing interception marks before returning. It validates the standard chain/whitelist structure, checks comments for idempotence, and rechecks every 15 seconds and before reconnecting. It never changes arbitrary VPN tables or kill switches. With unknown or missing VPN rules, it tries SSH over the existing routing without modifying them. Status is logged once at worker start or when routing status changes, not every polling interval. Other VPN configurations have no automatic bypass guarantee. Exclusions are runtime rules, recreated when needed; stopping the service stops the tunnel but leaves those two narrow rules until table recreation/reboot. The VPS setup changes only dedicated SSH users and their SSH Match restrictions, with backups; no VPS VPN settings are changed.

Release 4 upgrades an existing installation only when its profile matches. It preserves the installed tunnel key, SSH authorization, host pins and original backups. Previous owned scripts are backed up under `/etc/quiet-lantern/owned-before-v4/`; replacements are staged and syntax-checked before the service is restarted. The `version` marker makes repeated release-4 runs no-ops. An existing `disabled` marker always prevents an update or restart.

Copy/open starts the clipboard write and reserves a new blank tab synchronously in the click handler. It detaches the new tab's opener, waits for copying, then navigates only the new tab to LuCI. Clipboard denial closes the blank tab and reveals manual copying. If popups are blocked, a persistent `target="_blank"` link opens the router after copying. The instruction tab stays open.

VPS restrictions follow [OpenSSH's forwarding controls](https://man.openbsd.org/sshd_config). Dropbear host verification uses [HOME/.ssh/known_hosts](https://github.com/mkj/dropbear/blob/master/src/cli-kex.c); the service explicitly sets HOME=/root.
